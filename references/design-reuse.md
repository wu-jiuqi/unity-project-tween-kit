# 在后续项目中复用动画设计

工具包服务于新项目的交互制作。展馆用于理解和试验设计，组件承载实际实现；原素材让基准可复现，接入时可换成宿主自己的图片、字体和声音。沿用宿主的视觉规范与页面结构，不因使用本包就把新项目改成喵弹拆箱风格。

## 从需求选方案

下表指向已交付组件。按目的选择，参数基准读[参数说明](parameters.md)，具体接口和单位读[接入表](integration.md)，实际算法及原值查对应来源记录。

| 新项目的交互目的 | 选择 | 迁移时保留的设计关系 | 宿主要提供什么 |
|---|---|---|---|
| 按下有确认感，拖出可取消 | `UIBounce` | 固定命中根、视觉子层形变；按下、抬起、移出各自反馈 | Button、视觉层、点击事件 |
| 二态设置清楚地滑动切换 | `SettingsSwitch77` | 滑块过渡与最终值一致；刷新表现不提交设置 | 设置值读写、开关容器 |
| 弹窗进入、退出有层次 | `ModalMotion` | 透明与缩放协同；关闭和连续开合可收敛 | 面板、CanvasGroup、宿主输入门控 |
| 物品飞向资源栏，建立获得感 | `RewardFlight` | 弧线、入场脉冲、靠近时缩小；终点在同一坐标空间 | 起点、目标栏、坐标换算；奖励由业务先确定 |
| 数字变化可被看见 | `NumberRoll` | 一段明确起止值与时长；可在到达事件后触发 | TMP、业务算好的From/To |
| 得分到达更醒目 | `ScoreImpact` | 分数变金色与相对放大同时到峰值，再回到原色/比例 | TMP、已更新的显示分值、到达事件 |
| 连续加分不刷屏 | `ScoreGain` | .07秒重新计时合并，提示再上浮淡出 | 正整数增量、文字和CanvasGroup |
| 目标/步数变化有反馈 | `TaskArrival`、`MovesFeedback` | 视觉层挤压、完成印章；进度仍由宿主决定 | 更新后的数值、完成布尔值、视觉子层 |
| 评价、排行或换景 | `CheerBurst`、`LeagueJelly`、`ThemeDissolve` | 字图爆发、衰减抖动或旧背景SmoothStep淡出 | 评级、数据更新事件或新旧背景 |
| 真实加载进度需要平滑呈现 | `LoadingProgress`、`StartupLoadingPresentation` | 单调追赶、完成门控、弹珠与完成星光 | 宿主任务进度和明确的Complete信号 |
| 页面与列表更新更连贯 | `PageSlide`、`GroupStagger`、`RankReorder` | 横移、原比例错峰、稳定身份的行位移 | 页面目标坐标、视觉层、新顺序 |
| 教学与轻提示不干扰操作 | `TutorialGesture`、`HintFade` | 手势与目标强调、活动后提示淡出 | 指示起终点、真实输入状态 |
| 闲置装饰和欢迎语更有层次 | `DecorativeBreath`、`PendantSwing`、`HomeLayeredFeedback` | 相对原姿态呼吸、视觉弹簧与分层延迟 | 独立视觉层、宿主冲量或入场事件 |
| 标题或品牌有入场记忆点 | `JellyLogoIntro`、`HomeWordmarkWiggle` | 逐字错峰、落定或周期波浪 | 自己的字图、布局与允许播放的时机 |
| 插画持续有轻微生命感 | `UIFloat` | 基准位置上的周期偏移与相位 | 独立视觉层、适配尺寸后的幅度 |
| 卡片或拖拽反馈更柔软 | `ActivityJellyMotion`、`EncouragementDrag` | 弹性与阻尼共同控制回弹；松手和取消能归位 | 视觉层、指针转发或拖拽对象、业务门控 |
| 命中方向清楚、物体有挤压感 | `JellyHit` | 方向与形变关联；视觉层独立于碰撞层 | 方向、视觉对象；伤害仍由宿主管理 |
| 开局目标、充能与结算需要编排 | `CollectionGoalEntrance`、`StarChargeView`、胜败/奖章组合 | 对象到达、数字反馈与下一段的先后关系 | 真实目标对象、结果快照、宿主回调与去重 |

最后一行属于宿主适配配方。先评估层级借用、坐标转换、事件去重和页面关闭，再估算工作量。单段数字滚动不代表完整结算计分系统已经交付。加载和序列帧等其他已交付内容见接入表；未提取项查[来源目录](catalog.md)，不可承诺直接导入可用。

## 从基准迁移到宿主

1. 检查当前工程：目标对象、布局缩放、Canvas/世界坐标、输入系统、暂停方式，以及已有动画组件。使用已有上下文，只有缺少影响设计的信息时才询问用户。
2. 在展馆体验对应操作，观察开始、进行、完成和取消；记下实际组件、原参数、曲线及时间来源。可保存参数JSON。需要精确值时查源码，不凭观感编造。
3. 先导入所需组件与依赖，用原示例跑通；将动画绑定到宿主视觉子层。按需替换原图片、字图、字体和音效，检查锚点、枢轴、切片和尺寸。文字字数或字图变化属于布局适配。
4. 从原参数开始调节。距离适配宿主设计单位；缩放幅度用相对倍率；时长、延迟和弹簧参数分别观察，避免只改全局速度掩盖问题。固定编排没有公开字段时，明确列出需要的代码适配及与原版的差异。
5. 验证真实操作、快速连续触发、暂停/恢复、切页、禁用和销毁。参数JSON只迁移同类型公开参数，对象引用仍需绑定。奖励、导航或提交事件由宿主负责，重播只演出。

例如“给新项目的商店购买按钮加反馈”：选择`UIBounce`，保持按钮命中区域固定，把形变目标绑定到按钮视觉层；使用商店自己的图标和字体，购买只绑定原业务事件。核对按下释放、拖出取消、禁用和快速连点，并记录相对原参数的调整。无需导入完整商店、奖励或结算流程。

完成时向接收者说明：选了哪个设计及原因、导入了哪些文件、绑定了哪些对象、怎样触发和停止、保留/调整了哪些参数，以及实际验证结果。来源证据用于复核；宿主接线才是本次交付。
